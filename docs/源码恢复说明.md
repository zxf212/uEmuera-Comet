# 源码恢复说明

> 这份文档解释一件事：**这个仓库不是原工程的副本，而是重建出来的。**
> 原始 Unity 工程（含全部 `.meta`、`Library`、最终 `ProjectSettings`）已被从磁盘删除且无任何备份，
> 本仓库由「上游仓库快照 + 编辑器本地历史快照 + 1 个反推文件 + 0.2 修复」拼合而成。
> 目的是让后来者清楚：哪些是原样的、哪些是推出来的、哪些已经永久丢失。

## 一、事件经过

| 时间 | 事件 |
|---|---|
| 2026-05-02 ~ 05-05 | 原工程在本地开发（目录名 `<原工程>`），期间产生 0.1 APK |
| 2026-05 ~ 10 | 工程目录被删除，无 git 仓库、无云备份、无 U 盘副本 |
| 2026-10-26 | 尝试恢复：先在上游 GitHub 仓库找到 05-02 的快照；再在 Trae 编辑器的本地历史里找到 05-02 ~ 05-05 的文件级快照 |
| 2026-10-27 | 拼合出可编译工程，逐项修复 Android 运行问题，产出 0.2 APK |

**关键事实：IL2CPP 产物无法还原源码。** APK 里只有 `global-metadata.dat` 的字符串表和方法签名，没有方法体，所以只能「验证成员是否存在」，不能「还原实现」。

## 二、恢复来源一：上游仓库快照

- 来源：`xerysherry/uEmuera` 的 Comet 分支仓库（本地快照目录 `uEmuera-Comet-main`）
- 代码状态：约 2026-05-02，128 个 `.cs`
- 用途：作为**底座**，提供完整的工程结构、`ProjectSettings`、`Packages`、场景引用

底座复制时排除了 `Library/`、`Logs/`、`UserSettings/`，因此首次用 Unity 打开会重新导入全部资源（数分钟）。

## 四、APK 侧取证：验证复原是否完整

源码是否复原成功，不能只靠「能编译」，要用 APK 反证。

### 4.1 方法

1. 从 0.1 APK 中取出 `assets/bin/Data/Managed/Metadata/global-metadata.dat`；
2. 解析其字符串表，定位 `Assembly-CSharp` 类型的成员名区间（本例为字节区间 **[20470, 25226)**）；
3. 把该区间内的标识符与源码编译产物的同名区间做集合比对，得到「APK 有 / 源码无」的差集。

### 4.2 结果

差集共 9 个标识符，其中：

| 类别 | 数量 | 判定 |
|---|---|---|
| Unity 编辑器产生的 `MonoScript` 引用数据 | 7 | 非代码，忽略 |
| 泛型反引号误报（`ConfigItem\`1`） | 1 | 误报，忽略 |
| **`ReadDimensions`** | **1** | **真实差异**：0.1 的 `BitmapTexture` 有 `_textureinfo` + `textureinfo` 属性 + `ReadDimensions()`；本仓库用 `TextureInfo` 缓存宽高实现等价功能 |

同时确认：`ColorMatrix` / `SetColorMatrix` / `InterpolationMode` / `HighQualityBicubic` **在 0.1 的 APK 里同样不存在** —— 这些是 Comet 分支的历史缺口，不是重建丢失的。

**结论：绘制链与加载链的成员级差异只剩 1 处，且功能等价。**

## 五、这个工程里「不是原版」的部分

### 5.1 反推补全

| 文件 | 情况 |
|---|---|
| `Assets/Scripts/Emuera/Content/IDrawContext.cs` | **整份文件为反推**。`UnityDrawContext : MonoBehaviour, IDrawContext` 引用了它，但接口本体从未在编辑器里保存过（历史中零命中）。按 `UnityDrawContext` 的 5 个 public 方法签名（`Clear` / `DrawTexture` / `DrawSprite` / `DrawRect` / `Resize`）补写。原版可能有更多成员或不同参数类型。文件头已注明。 |

### 5.2 被修改过的文件

| 文件 | 改动 |
|---|---|
| `Assets/Scripts/SpriteManager.cs` | 初版为修复编辑器下 DXT 纹理报错，两处 `new Texture2D(4,4,format,false)` 固定为 `TextureFormat.RGBA32`（0.2 又在此基础上做了按需解码改造） |
| `README.md` | 已改写为面向 GitHub 的版本（原文为 0.1 时期的草稿，含未写完的条目） |

其余核心文件（`GraphicsImage.cs` / `Drawing.cs` / `EmueraContent.cs` 等）与历史快照**逐字节一致**（`cmp` 校验通过）。

### 5.3 永久丢失的部分

| 项 | 说明 |
|---|---|
| **05-04 之后的改动** | 历史里 `SpriteManager.cs` 只到 05-04 14:26，`GraphicsImage.cs` 到 05-05 18:48，不同步。中间是否有未记录的改动，**无法确定** |
| `ProjectSettings` 最终值 | 历史里是 05-03 11:21 的状态（`bundleVersion: 0.2.9d`、`applicationIdentifier` 为空），而 APK 实际是 `com.uemuera.comet` / `0.1`。那次改动没有进入历史，本仓库只能按 APK 的实际值回填 |
| 全部 `.meta` | 首次用 Unity 导入会生成新 GUID。场景 `Main.unity` 只引用了 `MainProject` 的 3 个脚本（`MainEntry` / `OptionWindow` / `EmueraMain`），GUID 均存在，不会丢组件 |
| `Library/` | 编译缓存，本就不该进版本库 |
