### 2. ERH 双重加载（`f9e7a48`）

| 项 | 内容 |
|---|---|
| 修复前 | `emuera.log` 显示 ERH 被加载 **106** 次（实际文件 90 个），Lv2 报 `#DIM` 重复定义，末尾 `ERHの読み込み中にエラーが発生したため処理を終了しました` |
| 修复后 | 加载次数与实际文件数一致；`emuera.log` **未生成**（无任何警告达到写盘级别）；无终止消息 |
| 判定 | ✅ 通过 |

### 3. 内存溢出（`dc2bce1`）

资源规模统计（对 2540 张图直接解析文件头）：

| 项 | 数值 |
|---|---|
| 图片数 | 2540（2409 WebP + 131 PNG） |
| 总像素 | 13.9 亿 |
| RGBA32 单份 | 5.18 GB |
| 纹理 + `pixelCache`（修复前） | **10.36 GB** |

运行数据（6 GB MuMu）：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| Native Heap | **3.65 GB** + 1.77 GB swap | **22 ~ 42 MB** |
| TOTAL PSS | 溢出 | 约 2.59 GB |
| 进程存活 | 约 45 秒被 `lowmemorykiller` 杀掉 | 90 秒以上持续存活 |
| OOM 记录 | `Kill 'com.uemuera.comet' ... to free 3652428kB rss` | 无 |

文件头解析自检：2540 张图 **0 失败**（WebP 的 VP8X / VP8L / VP8 三种子类型全部命中）。

降采样方案对照（说明为什么必须改成按需解码）：上限 640 px 时仍为 2.38 GB/份，无法在 6 GB 设备上安全运行。

判定：✅ 通过

### 4. 配置缺失兜底（`34a2b04`）

验证方法：在**模拟器**上把 `emuera.config` 改名（不动 PC 上的游戏文件，验证后已改回）。

```
[Config] path=.../emuera.config  exists=False  loaded=False  SearchSubdirectory=True
[LoadContents] done: 31 CSVs, 10142 sprites, 0 failed
```

无 `emuera.log`、0 条致命错误、正常进入标题画面。

判定：✅ 通过（且文件存在时行为不变，已验证）

### 5. 文件名大小写（`c71caf7`）

先复现，再验证：

| 检查 | 结果 |
|---|---|
| `find . -type f -name "CHARA*.CSV"`（严格大小写） | **0 个** |
| `find . -type f -iname "chara*.csv"`（忽略大小写） | **163 个**（`Chara0.csv`、`Chara1 霊夢.csv` …） |
| 同包 ERH 扩展名 | 94 个，全为大写 `.ERH` |
| 同包 ERB 扩展名 | 3903 个 = 3833 `.ERB` + 70 `.erb` |

真机症状：满屏 `警告Lv2:…M_KOJO_K129_INFO.ERB:9行目:定義していないキャラクタ変数を参照しようとしました` + `PRINTL %C%CSTR:(129:0)%`，角色编号 129/130/133/134/139/140/142/151/154/160… 全部未定义。

修复后真机：进入标题画面，上述警告不再出现，可正常操作。

判定：✅ 通过

## 三、安装包体积构成（0.1 vs 0.2）

| 项目 | 0.1 APK | 0.2 APK |
|---|---|---|
| `libunity.so`（arm64 + armv7） | 8.29 + 8.00 MB | 4.70 + 4.28 MB |
| `libil2cpp.so`（arm64 + armv7） | 7.12 + 7.16 MB | 6.42 + 6.40 MB |
| `assets/bin/Data` | 13.02 MB | 9.78 MB |
| `global-metadata.dat` | 1.29 MB | 1.17 MB |
| 条目间全零死空间 | **20.43 MB** | **0 MB** |
| APK 总计 | 66.3 MB | 33.6 MB |

死空间验证：0.1 的 zip 数据区存在 6 段空洞（4.3 MB / 7.3 MB / 5.9 MB / 1.2 MB × 2 / 0.86 MB），随机抽样 480 KB 检查，非零字节 70 个（**0.0142%**），判定为填充垃圾。0.2 为干净构建，无此类空洞。

## 四、明确未验证的部分

| 项 | 说明 |
|---|---|
| 其它 era 游戏 | 只测了 2 个发行包，其他游戏（eraTW 各版本、eraocg 等）未回归 |
| 长时稳定性 | 未做 1 小时以上连续游玩测试；纹理回收（60/120/300 秒）后的再解码行为未压测 |
| 首次绘制延迟 | 按需解码带来的首次显示延迟未量化（主观感受为几十毫秒级） |
| GXX 画面级回归 | 未用重度依赖 `GDRAWSPRITE` / `GSAVE` 的游戏做像素级对比 |
| 真机 Android 版本差异 | 只在一台真机上验证；Android 14/15/16 的文件系统行为差异未逐一测试 |
| `IDrawContext` 签名 | 该接口为反推补全，若原版签名不同，`UnityDrawContext` 编译可能需微调（当前可编译） |
